## 共同的現況（程式碼事實，動手前不用再查一次）

**詞綴在哪決定**：`js/07 rollAffixesNew(baseChance)` 是唯一入口，回 `{attr:false, bless:骰中, anc:false}`。
`anc` 恆 false ＝上游把遠古系停產（欄位、四階效果、名稱前綴、排序、堆疊簽章全都還在）。
`afk-ancdrop` 就是包這支把 `anc` 補回去的。

**誰會呼叫它**：
- `js/08 gainItem`：一般掉落、製作、NPC 兌換、遺物布告欄——**全部走這條**（含 afk-offline 的離線結算，它 1:1 重放核心 killMob）
- `js/04 pledgeBonusDrop`：血盟／攻城敵人的攜帶物（自己組 instance，不走 gainItem）
- `js/14 pandoraStockBless`：黑市上架當下決定祝福（**已明文排除遺物**）

**祝福／遠古實際給多少**（`js/08 applyBlessStats` / `applyAncStats`）：

| | 武器 | 防具 | 飾品 |
|---|---|---|---|
| 祝福的 | 傷害+1、命中+1、額外魔法點數+2 | AC-1、傷害減免+1 | AC-1、MR+1 |
| 遠古 | 傷害+2、魔傷+1 | 傷害減免+2 | 傷害減免+1、MR+1 |
| 永恆 | 傷害+4 | AC-2 | 傷害+1、AC-1 |
| 不朽 | 命中+4 | ER+2 | 傷害+1、命中+1 |
| 太初 | 魔傷+2 | MR+4 | MR+2、額外魔法點數+2 |

⚠️ 祝福另有**賣價 ×10**（`js/10:1817`），這不是純戰力問題，是經濟問題。

**現行祝福機率**（`baseChance`，由呼叫端傳入）：一般掉落 1%、頭目 10%、**製作 10%**；席琳的世界會在 `rollAffixesNew` 內部再乘（頭目 20%／瘋狂 30%、一般怪 ×3／×5）。

**裝備收集冊現成 API**（`js/16-equip-book.js`，全域函式可直接用）：
- `EQUIP_ITEM_CAT[itemId]` → 分類 key；`EQUIP_CATEGORIES` 共 27+1 類
- `equipCatCount(ck)` → `{got, total}`；**`equipCatComplete(ck)` → 該分類是否全收集**
- 該分類收集滿本來就有永久加成（`EQUIP_CAT_BONUS`）→ 玩家早就在追這件事，也早就看得到進度（收藏面板）

**遺物現在被擋在哪**（四處各自獨立，本文只動第一處）：
`js/08:118` 不附任何詞綴 ／ `js/08:1138` 不可強化 ／ `js/11:996` 不可賦予屬性 ／ `js/01:921` 不附席琳套裝。

## 案一：製作可出遠古系（分類收集滿才開放）

### 規則提案
製作出來的**武器／防具／飾品**，若「該成品所屬的裝備分類」已在裝備收集冊全收集完成，
則以**與製作祝福相同的機率（現為 10%）**附加遠古系詞綴，四階等機率各 25%。
祝福照舊（含「用祝福材料 → 成品必定祝福」那條），兩者互不影響、可同時出現。

### 掛接
1. 包 `doCraft(npcId, recipeIdx)`：進去時記下 `recipe.result`，`finally` 清掉（跟核心自己 `_tradLootCtx`／`_forceBless` 同一個做法）。
2. 沿用 `afk-ancdrop` 已經有的 `rollAffixesNew` 包裝，多加一個「製作」來源分支：
   有製作旗標 → 查 `equipCatComplete(EQUIP_ITEM_CAT[成品id])` → 通過才擲。
3. 機率**不自己訂死**，直接用核心傳進來的 `baseChance`（製作路徑就是 0.10）——上游改製作祝福率會自動跟上。

🚨 **順序不可寫反**：掉落亂數是 committed RNG（`lootRng` 吃存檔裡的 `player.lootSeq`），
多消耗一個序號會位移**之後所有**掉落結果 → 必須「先確認分類已收集滿，才呼叫 lootRng」。
這條 `afk-ancdrop` 檔頭已經寫過，實作時照抄。

### 邊界（都已確認過）
- 寵物裝備（`petwpn`/`petarm`）：核心 `_noAffixCtx` 已擋成白板 → 天生不受影響。
- 一次製作多件：`gainItem` 逐件呼叫 → 每件各自擲，符合直覺。
- 傳承式製作（火影／魯米爾的「消耗 +11 以上武器」）：那條路是**繼承來源的 en/attr/bless/anc**、
  不走 `rollAffixesNew` → 不必動，來源是遠古就繼承遠古。
- 沒有任何製作配方會產出遺物（248 個配方掃過），所以案一與案二不重疊。

### 要補的說明（不然玩家不會知道）
- 製作面板：該類已收集滿時標一行「此分類已收集完成 → 有機會做出遠古系」。
- 裝備收集冊分類頁首同一句。
  （比照 `afk-ancdrop` 在卡片收集冊頁首補的那句——玩家正是在那裡決定要不要湊。）

### 開關歸屬
併進 `afk-ancdrop`，開關改名「**遠古系裝備來源**（金卡怪掉落／製作）」一顆管兩個來源。
理由同狀態欄補充那次：同一件事、同一個掛法，拆兩顆只是多一個要勾的。

### 要你決定
1. **門檻**：整類收集滿才開放（你原本的講法），還是「收集率越高機率越高」？——我建議整類滿，判準單純、玩家看得懂。
2. **機率**：沿用製作祝福的 10%，還是另外訂（例如 5%）？——我建議沿用，不必兩邊各記一份數字。
3. **要不要排除某些分類**：例如「其他武器」目前是空的（`total=0` → `equipCatComplete` 回 false，天生不會誤判，不必特別處理）。

## 案二：遺物可帶祝福／遠古

### 為什麼外掛包不住（要核心補丁）
`js/08:118` 的條件裡就寫著 `!isRelic(d)` → 遺物**根本不會呼叫** `rollAffixesNew`，
包那支沒有用。而包 `gainItem` 事後補寫也不行：詞綴要在「決定併進哪個堆疊」之前就定案
（`itemSig` 含 bless/anc），事後改會把**整疊**一起改掉（同款遺物拿到第二件就出事）。

→ 走 `scripts/apply-core-patches.mjs` 加**第 10 組補丁（1 處錨點）**，
把那個條件改成「遺物也放行，但要問外掛」：外掛沒載入／開關關掉時行為與上游完全相同。
做法比照現有的 `__afkTradRollEn` 鉤子（補丁 2），核心只留一個問句，規則全在外掛。

### 開了之後哪些路徑會有、哪些不會

| 取得路徑 | 會不會帶祝福／遠古 |
|---|---|
| 玩家 NPC 掉落遺物（0.001%·`js/04 playerNpcRelicDrop`） | ✅ 走 gainItem |
| 潘朵拉遺物布告欄（`js/24`） | ✅ 走 gainItem |
| NPC 兌換／任務給的遺物 | ✅ 走 gainItem |
| 黑市（潘朵拉）上架的遺物 | ❌ `pandoraStockBless` 另有一道 `isRelic` 排除（要不要一起開是另一個決定） |
| 血盟／攻城攜帶物（`js/04 pledgeBonusDrop`） | ❌ 那條路本來就抽不到遺物 |

遠古的部分：`afk-ancdrop` 現行規則是「該怪已開金卡」，而遺物掉落來自玩家 NPC／布告欄——
**兩者的 `_lootMobInfo` 情境不同**，所以要另外決定遺物的遠古條件（見下方待決定 2）。

### 影響與風險
- **動到一條明講過的設計**：遺物「數值永遠固定、永遠維持單一能力」是上游刻意的（相關註解四處）。
  開了之後遺物會有「有沒有祝福／哪一階遠古」的追求，好處是遺物多一個目標，壞處是同一件遺物有優劣之分。
- **賣價 ×10**：祝福的遺物賣價會是十倍。遺物本身 `p: 10000` 級距，影響不算大但要知道。
- **說明文字要一起改**（不改就是騙人）：掉落查詢「遺物」那條現在明寫「遺物無法強化，也**不會**帶祝福／詛咒、屬性／遠古詞綴——數值永遠固定」。
  要改成「本站開放了祝福與遠古（可在外掛開關關掉）；仍不可強化、不可賦予屬性、不附席琳套裝」。走 `/update-wiki`。
- **不會連帶開放的**：強化、賦予屬性、席琳套裝——那是三處各自獨立的判斷，不動就不會變。
- **詛咒不會誤中**：`rollAffixesNew` 只會回 `bless: true/false`，`'cursed'` 只有詛咒卷軸給得到。
- **同步上游**：多一組錨點要對；錨點掉了 `--check` 會 exit 1 大聲失敗（不會安靜壞掉）。

### 要你決定
1. **祝福要不要開**、**遠古要不要開**（可以只開一個）。
2. **遠古的條件**：跟裝備一樣要求「遺物收集冊該分類收集滿」（`js/21` 有獨立的遺物收集冊，同樣有分類與 `equipCatKey`），還是無條件跟著祝福一起擲？
3. **黑市上架的遺物**要不要一起開（要多一個小改動）。
4. **預設開還是預設關**：這條改的是遊戲設計而不是介面，我傾向**預設開但獨立一顆開關**（跟 `ancdrop` 分開，因為不喜歡的人會想只關這個）。
